# 1. Autonomous Rust Dumper with Conservative Field Optionality

We maintain an autonomous native Rust tool (`dumper_rust`) using MSVC RTTI parsing and `iced-x86` instruction decoding as the primary protocol schema extraction pipeline. Its output (`packets_rust.json`) serves as the primary schema source for external SDK codegen as well as protocol datamining, replacing the legacy Binary Ninja dump. For field validation semantics, fields default to `required: false` unless an explicit runtime registration flag (`1 = required`) is proven in assembly, ensuring generated clients are resilient to server-side schema evolution.

## Context

The project previously relied on IDA Pro Hex-Rays scripts and Binary Ninja IL analyzers to dump `core.dll`. IDA required expensive commercial licenses with decompiler plugins, while Binary Ninja took minutes and had truncated type strings. Neither provided a repeatable standalone CLI pipeline. Furthermore, strict `required: true` markings on fields caused generated SDK clients to crash or reject valid server payloads during minor protocol updates, and downstream SDK generators had to maintain fragile heuristics, hardcoded opcode lookup tables, and C++ string parsers to consume raw dumps.

## Decision

1. **Autonomous Tooling & Primary Codegen Source**: Build and maintain `dumper_rust` in Rust using `goblin` (PE headers), `msvc-demangler` + custom RTTI traversal (inheritance and vtables), and `iced-x86` (disassembly), running complete extraction within 20 seconds and emitting `packets_rust.json` as the primary schema source for external SDK code generation.
2. **Schema Invariants & Recursive Type Decomposition**: Combine IDA's precision in structural boundaries (rejecting dispatchers/converters) with clean decomposed type signatures (`int32_t`, `int64_t`, `char`), stripping C++ `struct`/`class`/`enum`/`union`/`const`/`volatile` qualifiers at all template nesting depths, unwrapping `Utilities::StrongTypedef<T>`, flagging binary byte arrays (`bytes: true` for `std::vector<std::byte>` and `std::vector<char>`), and recursively decomposing map key/value types (`map_key_type` and `map_value_type`).
3. **Conservative Optionality**: In generated **Models** and **Polymorphic Models**, treat **SerializableMember** fields as `required: false` by default unless explicitly asserted by runtime flags, matching real-world protocol resilience.
4. **Dual Naming (`name` + `ident`)**: Preserve full demangled C++ namespaces in `name` across all **Packets**, **Events**, **Models**, and **Polymorphic Models** for datamining, while emitting normalized, collision-free PascalCase `ident` identifiers (including canonical operation `name` and `ident` on **Packets** and **Events**, and deterministic prefix disambiguation such as `LogEventParams` vs `LogLogEventParams`) for direct SDK code generation.
5. **Standalone `models` vs `polymorphic_models` Separation**: Exclude **Polymorphic Model** base types, active `variants`, and `rtti_subclasses` from the top-level `models` array so `models` contains strictly standalone **Models** (including standalone **Models** transitively reachable through polymorphic variants), while preserving `rtti_subclasses` and `root_sources` inside `polymorphic_models` for datamining.
6. **Automatic Ownership Cycle Detection (`recursive: true`)**: Analyze the directed non-indirected ownership graph across **Models** and **Polymorphic Models** (ignoring `array` and `map` container indirections) and mark cycle-closing fields with `recursive: true` so statically typed SDK generators can emit heap indirection (`Box<T>`) automatically.
